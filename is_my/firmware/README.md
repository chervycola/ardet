# Is My — прошивки (скелеты, It-1…3)

```
firmware/
  common/midi_map.h    — ЕДИНСТВЕННЫЙ источник MIDI-маппинга (§C1)
  pult/                — пульт на доноре DJI C5: оси→14-bit CC, органы (05_pult_dji_c5.md)
    main.c, bsp.h
  module/              — модуль: USB-MIDI→CV, FSM mute, DAC8568, линк, VBUS (§C3)
    main.c, bsp.h, dac8568.h
  host_test/           — тесты логики на обычном gcc, без железа
    build.sh, smoke_module.c, smoke_pult.c
```

Связь пульт ↔ модуль — один кабель USB-C: модуль — USB-host и источник питания, пульт —
class-compliant USB-MIDI устройство без батареи. TRS-MIDI, опторазвязки и LiPo больше нет.

## Принцип

Логика написана в чистом C поверх тонкого **BSP-интерфейса** (`bsp.h`).
HAL/CubeMX-код в репо не живёт: под отладочную плату создаётся обычный проект,
в нём реализуется `bsp_*.c` (список функций — в `bsp.h` каждой стороны),
а `main.c` и `midi_map.h` подключаются как есть.

## Что настроить в железе

**Пульт (Nucleo-G431KB → своя плата в корпусе DJI):**
- ADC1: четыре оси гимбалов + dial; oversampling ×16, right shift 0 → 16-bit
- USB Device FS: класс Audio/MIDI (или tinyusb-MIDI); питание от VBUS, Rd 5.1k на CC
- GPIO: кнопки RTH / Fn / Shutter / Power, слайдер MODE, четыре LED
  (если у донора кнопки на резистивной лестнице — один канал ADC, см. R18)
- Flash: последняя страница под `cal_t`

**Модуль — две ветки, выбор по итогам It-2 (решение D6):**
- A: STM32G431 + MAX3421E по SPI (стек USB Host Shield / USBH_MIDI как референс)
- B: RP2040 (Pico) + TinyUSB host + `usb_midi_host`

Общее для обеих:
- USB-host стек разворачивает USB-MIDI пакеты в сырые байты → `bsp_midi_rx_pop()`;
  `bsp_midi_link_up()` — устройство энумерировано
- SPI: DAC8568 (mode 1, 32-bit кадр = 4 байта, SYNC вручную), отдельно от шины host-контроллера
- Линии CC1/CC2 на ADC или компараторы → `bsp_usb_sink_attached()` (антидребезг ≥ 100 мс),
  ключ VBUS TPS2553 → `bsp_vbus_enable()`
- GPIO: три линии топологии ядра (реле + ключи, см. `bsp_mux_set_mode`), линия ROUTE,
  панельный свитч ROUTE, LED ACT и ARM

## Что уже в логике

**Пульт**
- Четыре оси 14-bit: EMA, порог отправки, rate-limit 200 Гц, края и центр шлются всегда
- Вертикали (DRIVE, CUTOFF) — rate: отклонение задаёт скорость, значение держится.
  Интегратор считает прошедшее время, а не вызовы; провал цикла дольше 50 мс не даёт скачка
- Горизонтали (BIAS, RESO) — momentary: позиция, deadzone у центра, ровно 8192 в покое
- Калибровка min/max/center во flash; сервисный жест — Power при подключении кабеля.
  Центр усредняется по 64 отсчётам; негодный результат не записывается (три вспышки LED)
- ARM и LINK — toggle от кнопок, MODE — слайдер, GATE — Shutter (нота C2), dial → CC#20
- Active Sensing (0xFE) каждые 250 мс; стартовый снапшот состояния после включения

**Модуль**
- Парсер: running status, realtime-байты его не сбивают, MSB→LSB с таймаутом 20 мс
  (fallback MSB<<7), чужой канал игнорируется
- Стартовая нейтраль: DRIVE и CUTOFF = 0 В, BIAS, RESO и dial = центр (0 В), mute, VBUS выключен
- FSM mute для MODE и ROUTE: S-образная рампа 30 мс вниз → переключение в тишине →
  пауза 10 мс → рампа вверх. Запрос, пришедший посреди цикла, не теряется;
  из нескольких запросов исполняется последний
- ARM — глобальный gate через тот же mute-канал, плавно; смена ARM посреди рампы без скачка
- GATE — одной записью сразу по событию (фронт формирует RC на выходе канала)
- Линк: жив, пока USB-стек видит пульт и байты идут чаще 500 мс. При потере оси держат
  последние значения, GATE отпускается
- VBUS включается только при детекте устройства на CC
- Канал G ЦАП — опора тока покоя серв ядра (S4.3)

Полярности и каналы ЦАП — в `module/dac8568.h`, маппинг — в `common/midi_map.h`.

## Хост-тесты

```
cd host_test && ./build.sh
```

Собирает оба скелета, гоняет `smoke_module` и `smoke_pult` на заглушках BSP, затем повторяет
оба теста под AddressSanitizer и UBSan. Тесты крутят настоящие шаги главных циклов
(`module_step`, `pult_step`) с шагом 1 мс, поэтому проверяют не только конечные состояния,
но и форму рамп, порядок событий и поведение во времени.
