## 0. Карта системы и разбиение на устройства

Два устройства, связанных одним кабелем USB-C. Модуль — USB-host и источник питания,
пульт — USB-MIDI устройство:

```
┌──────────────────────────────┐   USB-C: MIDI + 5 В   ┌──────────────────────────────┐
│  ПУЛЬТ (донор DJI C5)         │ ◀───────────────────▶ │  МОДУЛЬ (Eurorack 3U, 20HP)   │
│  • два стика, 4 оси           │   данные → модуль      │  • USB-host → MCU → ЦАП       │
│  • слайдер MODE, кнопки       │   питание → пульт      │  • MOSFET-ядро (3 режима)     │
│    ARM / LINK / GATE, dial    │                        │  • фильтр + выходной VCA      │
│  • своя плата STM32G431       │                        │  • 8× CV in, 3× CV out        │
│  • без батареи, без CV-out,   │                        │  • 9 ручек, 2 свитча          │
│    без сверловки корпуса      │                        │  • питание ±12V из шины       │
└──────────────────────────────┘                        └──────────────────────────────┘
```

Ключевое следствие архитектуры «связь = MIDI, не CV»: **модуль обязан иметь микроконтроллер и ЦАП**, иначе он не сможет превратить присланные по MIDI данные стиков в управляющие напряжения для аналогового ядра. Пульт CV не передаёт — он шлёт MIDI; модуль регенерирует CV локально. CV-выходы X/Y/GATE для остальных модулей линейки стоят на панели модуля.

**MCU пульта — STM32G431**: 12-bit ADC с аппаратным оверсэмплингом до 16 бит (критично для 14-bit осей) и USB FS device. **MCU модуля — по итогам It-2** (решение D6, R19): STM32G431 с внешним host-контроллером MAX3421E либо RP2040 со встроенным USB-host. Аналоговых входов модулю почти не нужно (только линии CC), поэтому слабый ADC RP2040 здесь не мешает — см. §13-R7.

# ЧАСТЬ A. МОДУЛЬ

## A1. Питание и шина

Вход: ±12V Eurorack (10-pin / 16-pin Doepfer, красная полоса = −12V).

Шины питания на плате (узловая схема — S0):
- **+12V / −12V** — аналог (буферы, OTA, фильтр, VCA, аттенюверторы, реле).
- **+9V ядра** — отдельный стабилизатор из +12V (78L09 или LM317L с подстройкой): нагрузки стоков MOSFET и драйвер затворов. Напряжение ядра задаёт уровень клипа.
- **+5V** — цифровая, **buck-преобразователь** из +12V (TPS54202 / LMR51420). Не LDO: от этой шины через гнездо USB-C питается ещё и пульт.
- **+3.3V** — MCU, ЦАП, USB-host; из +5V через **MCP1700** / **AP2112**.
- **Опорное Vref +4.096V** (для ЦАП) — **REF3040** / **ADR4540**, отдельно отфильтрованное.

Развязка цифра↔аналог: ферритовые бусины между +5V/+3.3V цифровыми и аналоговыми землями; единая звезда земли в точке входного разъёма. ЦАП-выходы выходят в аналоговую область — там аналоговая земля.

Защита входа: последовательные диоды / P-MOSFET reverse-polarity, TVS на ±12V, предохранитель-полимер (PTC) по каждой шине.

Питание пульта: VBUS гнезда USB-C через ключ с токовым лимитом TPS2553. Ключ включается только после того, как на линиях CC обнаружено устройство (S11.2), — в чужой host или хаб 5 В не подаём.

Бюджет тока — см. §10.

## A2. Входной буфер (AUDIO IN)

- Разъём: 3.5mm Thonkiconn, моно (TS), нормированный (switched) — нормаль не используется для аудио, но контакт пригодится для индикации «вставлен ли кабель».
- Схема: неинвертирующий буфер на **TL072 / OPA1642** (FET-вход, низкий шум), Zin ≈ 100 кОм, усиление ×1. AC-связь на входе (большой плёночный конденсатор + резистор смещения к аналоговой земле). Клампинг-диоды (BAT54S) к ±12V (или к рельсам ОУ) на входе для защиты от перегруза.
- Модулярный уровень: рассчитываем на ±5V (10 Vpp) номинал, headroom до ±10V. Перед ядром — нормировочные делители, чтобы ввести сигнал в рабочую область MOSFET (план уровней — S1, делители — S4.1/S4.2).

## A2.5. Пред-core тракт (variable HPF + INPUT DRIVE + clean tap)

Решение: **вся нелинейность остаётся в MOSFET** (принцип §10) — структура «двухкаскадный клиппер + пред-фильтр + параллельный чистый тракт», но без диодно/LED-клиппинга. Узлы пред-core формируют сатурацию:

**Полный сигнальный путь (SHAPER + резонансный фильтр, переключаемый pre/post):**
```
AUDIO IN → buffer ─┬→ pre-HPF(var) → INPUT DRIVE ─┐
                   │                               ▼   ┌──── ROUTE switch (pre/post) ────┐
                   │                          [ MOSFET core (s1→s2) ] ⇄ [ RESONANT VCF ] │
                   │                               └──────────────┬──────────────────────┘
                   │                                              ▼
                   │                                   TONE (tilt) → BASS (low shelf) ─┐
                   └→ clean tap ───────────────────────────────────────────────────────┤
                                                                         MIX (dry/wet) → VCA (2 каскада) → AUDIO OUT
```
ROUTE = pre: фильтр **до** сатурации (фильтр-свип определяет, что искажается). ROUTE = post: фильтр **после** (классика — режем грязь). Переключатель на панели, коммутация — под mute (A7).

Узлы пред-core (порядок и план уровней — S1 в `03_schematics.md`):
- **pre-HPF (variable)** — *ключевой тембральный контроль*. ВЧ-фильтр сразу после входного буфера, **перед** усилением и MOSFET-каскадом, перестраиваемый ~20 Гц … ~2 кГц:
  - полностью CCW (срез 20 Гц) → весь низ влетает в транзистор → жирная басовая дисторшн;
  - выше (срез растёт) → низ срезан до клипа → тонкий «осиный» fuzz.
  - Реализация: интегратор на OTA (LM13700 с линеаризующими диодами) и вычитатель; срез по сумме «ручка HPF + HPF-CV» (S3).
- **INPUT DRIVE** — управляемый предусилитель перед ядром: сухой путь плюс OTA. Это и есть «Drive» из концепта. На нуле DRIVE каскад не закрывается, а отдаёт «пол» — сигнал на границе клипа; на максимуме вгоняет ядро в глубокий клип. Ход усиления ×1…×22 (S2, R23).
- **clean tap** — чистый отвод сигнала **сразу после входного буфера** (до HPF и ядра), буферизуется и идёт на MIX (clean blend, A8). Сохраняет фундамент и транзиенты под тяжёлой сатурацией — критично для баса.

Пред-core (pre-HPF, INPUT DRIVE) и MIX/BASS — **глобальны** (действуют во всех трёх режимах ядра), а двухкаскадная топология (ниже) — конфигурация именно SHAPER; в RING/GATE транзисторы перекоммутируются в ключи (A3.2/A3.3). Одно исключение: в RING усиление INPUT DRIVE фиксируется, потому что DRIVE там задаёт частоту несущей.

## A3. MOSFET shaper core — ядро

Сердце модуля. Используется **силовой N-канальный MOSFET из донорского ESC** (logic-level, low-Rds(on), типичный корпус DFN/SOT-23 для мелких ESC или DPAK для крупных). Конкретный тип каждого экземпляра документируется в provenance (§A3.6).

Два транзистора перекоммутируются между тремя топологиями (S4.4): силовые цепи стока и истока — сигнальными реле, затворы, входы и сервы — аналоговыми ключами **DG333A**. Логика выбора режима — от MCU (декодирует MODE из MIDI). Всё переключается **только под mute** (см. A7), чтобы исключить щелчки.

Общая идея: транзистор остаётся силовым переключателем/нелинейным элементом во всех режимах — функциональная преемственность (принцип §10 концепта).

### A3.1. SHAPER — двухкаскадный MOSFET-сатуратор

Брутальность даёт связка **двух каскадов клиппинга подряд**, но клиппит **сам ESC-MOSFET** (два каскада на транзисторах, диодов/LED нет — §10). Под SHAPER используются **два MOSFET** (оба из донорского ESC, A3.6): stage 1 — мягкое насыщение, stage 2 — жёсткий клип/компрессия.

**Stage 1 — мягкий транскондуктансный каскад:**
- Common-source, аудио на затвор через сумматор `Vgate = Vaudio·Drive + Vbias`.
- Работает у класса A. При токе покоя в доли миллиампера силовой MOSFET сидит под порогом: передача экспоненциальная, как у биполярного транзистора, усиление каскада порядка −50…−100. Клип несимметричен по природе; рабочая область (Iq, Rd, Vdd, делители) выбирается на It-4a по измеренной Id(Vgs) — R21.
- `Bias` смещает рабочую точку → асимметрия (чётные ↔ нечётные гармоники). **Bias = непрерывное управление характером клипа** (симм. ↔ асимм.), вместо дискретного переключателя.

**Stage 2 — жёсткий клип/компрессия:**
- Второй common-source с бóльшим gain, раскачивается **в отсечку и насыщение** → сток клиппит у Vdd/0 характеристикой самого транзистора (никаких диодов). Брутальная компрессия чисто на материале.
- Симметрия клипа здесь тоже зависит от рабочей точки stage 2 (общая Bias-цепь + локальное смещение).
- На больших Drive связка двух каскадов с локальной ОС/ёмкостью входит в **period-doubling** (саб-октава) — желаемо; глубина — номиналами на макете (R2).

**Сквозное:**
- Между каскадами — делитель и межкаскадная связь (AC); после второго каскада — буфер и anti-fizz LPF ≈ 15 кГц, чтобы укротить ВЧ-визг (S4.2).
- Нагрузка стоков — резистор/источник тока, `Vout = Vdd − Id·Rd` (инвертирующе, нелинейно).
- `Drive` (из пред-core, A2.5) задаёт, насколько жёстко влетаем в каскад 1 → глубина сатурации/компрессии (вход и усиление слиты в Drive).
- **Каждый каскад — со своей сервопетлёй термокомпенсации** (A3.4): дрейф двух транзисторов держится независимо. Дуальный low-offset ОУ (OPA2188).

`Level` (VCA gain из концепта) — первый каскад выходного VCA (A3b, S8). Level и Drive независимы: Level — общий уровень тракта на выходе, Drive — глубина захода в нелинейность MOSFET.

### A3.2. RING — кольцевая модуляция на ключах

Концептуальная фишка: транзисторы **буквально коммутируют** (как в дроне). Два ключа нижнего плеча открываются по очереди, как плечо моста в регуляторе хода.

Цепочка (S4.5):
1. **Несущий генератор** — аналоговый треугольный VCO, частота 200 Гц … 10 кГц от Drive: OTA-интегратор (LM13700) + компаратор-Шмитт (LM311).
2. **ШИМ-компаратор** — **LM311**: сравнивает сигнал с треугольной несущей → ШИМ, скважность которого следует за мгновенным уровнем аудио и за Bias.
3. **Драйвер затворов** (TC4428) раздаёт этот ШИМ на два MOSFET в противофазе, размах 0/+9 В.
4. Каждый MOSFET закорачивает на землю свой низкоомный узел: на один узел подан сигнал, на другой — он же в противофазе. Сумматор слышит то один, то другой: сигнал переворачивается с частотой несущей → боковые полосы, инхармоничность.
5. На низких частотах несущей слышен дискретный **тик** переключения — заряд затвора, впрыснутый в узел: «голос материала» (§3.2 концепта). Сохраняем намеренно; громкость тика задаётся сопротивлением узла.
6. Восстановительный LPF после сумматора — мягкий (1-й порядок, ~7 кГц), чтобы тик остался; глубину сглаживания можно вывести в Tone.

`Bias` в этом режиме сдвигает скважность: при 50 % прямой сигнал подавлен (чистый балансный модулятор), сдвиг подмешивает прямой сигнал. Глубина ШИМ от аудио добавляет самомодуляцию — подстроечник.

Запасной вариант для сравнения на It-5 — «класс D»: ключ рубит постоянный уровень, а звук несёт только скважность. Физику RING выбираем на слух (R22).

### A3.3. GATE — лимитер на транзисторе + ключ-гейт

- **Верхний порог (hard limit)** задаётся Drive: второй MOSFET работает усилительным каскадом и упирается стоком в рельсы питания ядра. Чем больше Drive, тем раньше сигнал достаёт до рельс. Диодов в звуковом тракте нет (решение D4).
- **Нижний порог (noise gate)** задаётся Bias: детектор огибающей на входе ядра против Bias-порога → если сигнал ниже порога, **первый MOSFET закорачивает тракт на землю** (опять буквальное переключение). Открытие быстрое, закрытие через 10–30 мс после спада → «режет хвосты», акцент на транзиентах (§3.2).
- Детектор огибающей: прецизионный выпрямитель и пиковый детектор на ОУ + компаратор **LM311** с гистерезисом. Диоды здесь — измерение, а не звуковой путь.

### A3.4. Термокомпенсация дрейфа

Силовые MOSFET имеют большой разброс и температурный дрейф порога `Vth` (≈ −2…−6 мВ/°C) и крутизны. Без компенсации рабочая точка SHAPER уплывает → меняется тембр и DC на выходе.

Решение — **сервопетля удержания тока покоя, по одной на каждый MOSFET-каскад** (SHAPER = 2 каскада, A3.1):
- Ток стока (или истока) каждого каскада измеряется по падению на малом резисторе истока `Rs`.
- ОУ-интегратор (**OPA2188**, дуальный low-offset — обе сервы в одном корпусе) сравнивает это падение с опорой `Iq_ref` и подстраивает **DC-смещение затвора** каскада так, чтобы ток покоя держался константой.
- Постоянная времени сервы — большая (≈ 0.5…1 с), чтобы петля компенсировала тепловой и долговременный дрейф, но **не реагировала на аудио и не съедала низ**. HPF в аудиотракте после ядра защищает от остаточного DC.
- Сигнал Bias от пользователя суммируется **поверх** сервы (серва держит среднее, пользователь модулирует вокруг).
- Серва держит *средний* ток, поэтому на сильном клипе рабочая точка «дышит» вслед за динамикой игры. Характер это или помеха — слушаем на It-4a.
- Когда транзистор работает ключом (RING, GATE), вход интегратора размыкается и серва хранит последнее смещение. Возврат в SHAPER обходится без секунд повторного захвата.

Это даёт «работоспособность в спецификации при уникальности звучания» (§6.3 концепта): серва гарантирует, что любой донорский MOSFET попадёт в рабочую зону, но тонкий характер каждого транзистора сохраняется.

### A3.5. Tone + Bass (пост-ядро)

- **Tone** — наклон спектра: **state-variable tilt-EQ** (одновременно поднимает низ/срезает верх и наоборот вокруг ~700 Гц) на одном ОУ. Управление Tone-CV через OTA для плавности. Наклон в обе стороны от пивота.
- **Bass** — отдельный **низкочастотный шельф** пост-ядро (~100–150 Гц), вернуть/убрать тело после сатурации. Простой shelving на ОУ, панельный knob (CV опционально). Дополняет Tone, не дублирует: Tone крутит баланс верх/низ, Bass — абсолютный уровень низа.

### A3.6. Привязка к донорскому MOSFET

- Под транзистор — **панелька/сокет или короткие выводные площадки**, чтобы каждый экземпляр edition получал свой ESC-MOSFET, а сервопетля адаптировалась к его параметрам.
- При входном контроле документируется: тип/маркировка (если читается), измеренные `Vth`, `gfs`, `Rds(on)` — в provenance certificate.
- Допуски, при которых серва ещё держит: `Vth` в диапазоне (определяется на макете, ориентир 1…4 В для logic-level). MOSFET вне диапазона — отбраковка/другой слот.
- **SHAPER теперь двухкаскадный → два сокета под ESC-MOSFET** (A3.1). По возможности оба транзистора — с одной донорской платы (общий провенанс экземпляра); серва компенсирует их разброс независимо.

### A3a. Резонансный фильтр — оригинальная схема «Поливокса» (VCF + ROUTE pre/post)

Фильтр собран по заводской схеме блока фильтра У4 синтезатора «Поливокс». Источники и расшифровка —
`refs/polivoks_vcf_vca.md`, узловая схема с номиналами — S5 в `03_schematics.md`. MOSFET-ядро (A3)
остаётся фузз-овердрайвом тракта; фильтр стоит до или после него (ROUTE).

**Топология:**
- 2-полюсный, 12 дБ/окт, выходы **LP / BP** (панельный свитч MODE-F).
- Ядро — два программируемых ОУ **К140УД12** (КР140УД1208) **без интегрирующих конденсаторов**:
  интегратором служит сам ОУ, срез задаётся током программирования.
- **RESONANCE** — заводская петля демпфирования с полосового выхода. Вместо потенциометра в ней
  стоит управляемый элемент (половина LM13700), чтобы сохранить CV-вход и стик пульта.
  На максимуме — **самовозбуждение**.
- **Filter Drive:** ограничителей амплитуды в петле нет, как в оригинале: на высоком резонансе
  ядро **упирается в рельсы питания** → радикальный дисторшн. Сохраняем намеренно.

**Управление:**
- **CUTOFF** — knob + CV-in приходят токами в узел управления; экспонента — на одном транзисторе
  в ОС ОУ, как в оригинале. Диапазон ручки — около десяти октав (уточняется на макете).
- **RESONANCE** — knob + CV-in. До самовозбуждения.
- **MODE-F** — панельный свитч LP/BP.

**ROUTE pre/post (панельный свитч):**
- Меняет порядок **MOSFET-core ⇄ VCF** (A2.5). Реализация — три SPDT одного корпуса DG333A (S6), **под mute**: панельный свитч ROUTE → GPIO MCU → тот же FSM, что и для MODE (A7).
- `pre`: фильтр-свип формирует спектр **до** клипа (что искажаем). `post`: режем грязь **после** (классика).

**Термостабильность:** экспонента среза не скомпенсирована, как в оригинале. Оценка ухода — около
полутора полутонов на градус; прогрев корпуса сдвигает срез на октаву и больше. Для арт-объекта
это часть характера «Поливокса»; решение о компенсации — после замера на макете. Помечено R16.

### A3b. Выходной усилитель — двухкаскадный VCA по схеме «Поливокса»

Собран по заводской схеме блока управляемых усилителей У5 (расшифровка — `refs/polivoks_vcf_vca.md`,
узловая схема — S8).

- Два каскада подряд, каждый — дифференциальная пара **К118УД1Б** и ОУ-вычитатель. Усиление пары
  задаётся током её хвоста. Вычитатели — на **TL072**: их входы работают у плюсовой шины,
  OPA1642 сюда не подходит (S8).
- **Каскад 1 — LEVEL**: ручка LEVEL + LEVEL-CV.
- **Каскад 2 — mute**: рампа ЦАП (канал F) для ARM и де-клика при смене MODE/ROUTE (A7).
  Ток хвоста в ноль = полная тишина.
- Характер даёт сама схема: на штатном уровне пара почти линейна, горячий сигнал (резонанс, фузз)
  мягко насыщает её.
- После VCA — выходной буфер (OPA1642), посл. резистор ~1 кОм, защита.

### A3.7. Параметры — сводка

| Параметр | Что делает | Ручка на модуле | CV-вход | Что приходит без кабеля |
|---|---|---|---|---|
| DRIVE | глубина захода в нелинейность; в RING — частота несущей; в GATE — верхний порог | аттенювертер | есть | левый стик Y, rate, 0…+5 В |
| BIAS | симметрия клипа; в RING — скважность; в GATE — нижний порог | аттенювертер | есть | левый стик X, ±5 В |
| CUTOFF | частота среза резонансного VCF | база | есть | правый стик Y, rate, 0…+5 В |
| RESONANCE | резонанс → самовозбуждение / Filter Drive | база | есть | правый стик X, ±5 В |
| MIX | dry/wet clean blend | база | есть | колёсико пульта, ±5 В |
| LEVEL | уровень выхода (первый каскад VCA) | база | есть | — |
| TONE | tilt верх/низ | база | есть | — |
| HPF | пред-клип ВЧ: бас-дисторшн ↔ тонкий fuzz | база | есть | — |
| BASS | пост-ядро НЧ-шельф | только ручка | нет | — |
| MODE-F | LP / BP фильтра | свитч | — | — |
| ROUTE | фильтр pre/post относительно сатурации | свитч | — | — |

Пульт играет четырьмя осями (DRIVE, BIAS, CUTOFF, RESO), колёсиком и кнопками; модуль лепит голос ручками и свитчами. Роли ручек — решение D2 (§A5, S9.2), полярности — решение D1 (§A6.3, S9.1).

## A4. (снят)

Видеосигнал в тракте модуля не обрабатывается: ни входа, ни узла, ни тока в бюджете. Тракт — чисто звуковой (R13 закрыт).

## A5. CV bus, нормализация, роли ручек

Восемь CV-входов на панели: **DRIVE, BIAS, LEVEL, TONE, HPF, MIX, CUTOFF, RESO**. Каждый:
- Разъём **switched** 3.5mm (Thonkiconn): нормаль-контакт замкнут, когда штекер не вставлен.
- На нормаль пяти входов подаётся **CV от ЦАП модуля** (регенерированный из MIDI):
  - DRIVE-in ← канал A (левый стик Y) · BIAS-in ← канал B (левый стик X)
  - CUTOFF-in ← канал C (правый стик Y) · RESO-in ← канал D (правый стик X)
  - MIX-in ← канал H (колёсико пульта)
  - LEVEL, TONE, HPF — без нормали (0 В).
- При вставке внешнего кабеля нормаль рвётся → внешнее CV перехватывает управление (как в §3.3 концепта).

На каждый параметр — одна ручка. Роль у неё одна из двух (решение D2, схема — S9.2):
- **DRIVE и BIAS — аттенюверторы** (−1…+1) над своим входом: глубина и знак жеста. Собственной базы на панели у них нет: база DRIVE — значение, накопленное на стике, база BIAS — рабочая точка сервы (§A3.4). Это и есть «настройка модуляции на модуле» (R12).
- **LEVEL, TONE, HPF, MIX, CUTOFF, RESO — ручка задаёт базу**, CV-вход суммируется с ней ×1. Глубину задаёт источник.
- **BASS** — только ручка, CV-входа нет.

Полярности нормалей — решение D1 (S9.1): накапливающие оси DRIVE и CUTOFF идут от нуля (0…+5 В), пружинящие BIAS, RESO и колёсико качаются вокруг нуля (±5 В). Два следствия: без пульта и без внешнего CV DRIVE стоит на полу (§A2.5), а левая половина хода его аттенювертера работает только с внешним биполярным CV.

## A6. USB-host, MCU, ЦАП, CV-выходы модуля

### A6.1. Вход от пульта: USB-host

- Разъём: **USB-C** на панели. Модуль — host: энумерирует пульт как class-compliant USB-MIDI устройство и питает его по VBUS.
- TRS-MIDI и опторазвязки нет (R1 снят).
- Host-часть — две ветки, выбор на It-2 (решение D6, S11): STM32G431 + MAX3421E по SPI либо RP2040 со встроенным host и стеком TinyUSB.
- VBUS: +5V через ключ с лимитом TPS2553, включается только после детекта устройства на линиях CC (S11.2).
- Стек разворачивает USB-MIDI пакеты в обычные MIDI-байты; дальше парсер тот же, что был бы у UART-MIDI.

### A6.2. MCU модуля

Функции:
- USB-host: энумерация пульта, приём USB-MIDI, контроль линка (Active Sensing и отключение устройства), питание порта по детекту CC.
- Парсинг MIDI (running status, 14-bit CC pairs, Note On/Off).
- Преобразование значений в коды ЦАП (с калибровочными таблицами на параметр).
- Драйв ЦАП по SPI.
- Управление топологией (MODE и ROUTE) → реле и аналоговые ключи через GPIO, с **mute FSM** (A7).
- ARM-логика (глобальный gate enable) → разрешение/запрет выходного VCA.
- Драйв индикаторов модуля (ACT, ARM) и чтение панельного свитча ROUTE.

### A6.3. ЦАП и каналы

**Октальный 16-bit ЦАП DAC8568 / AD5668** (SPI, внешний Vref). Каналы и диапазоны после масштабаторов:

| Канал | Назначение | Диапазон | Куда идёт |
|------|-----------|----------|-----------|
| A | DRIVE — левый стик Y, rate | 0…+5 В | нормаль DRIVE-in **и** CV-out «Y» |
| B | BIAS — левый стик X | ±5 В | нормаль BIAS-in **и** CV-out «X» |
| C | CUTOFF — правый стик Y, rate | 0…+5 В | нормаль CUTOFF-in |
| D | RESO — правый стик X | ±5 В | нормаль RESO-in |
| E | GATE | 0 / +5 В | CV-out «GATE»; опция принудительного открытия гейта (S4.6) |
| F | MUTE: рампа на второй каскад выходного VCA (S8) | 0…4,096 В | внутр. |
| G | Iq_ref серв (опора тока покоя ядра, S4.3) | — | внутр. |
| H | колёсико пульта → MIX | ±5 В | нормаль MIX-in |

CV-out X/Y/GATE дублируют левый стик и кнопку GATE: один и тот же канал ЦАП кормит и нормаль параметра, и выходной джек. «Y out» — накопленное значение DRIVE (0…+5 В), а не положение стика; «X out» — положение стика (±5 В).

Постобработка ЦАП: ОУ-масштабатор каждого канала под диапазон из таблицы (R5, решение D1). RC-сглаживание (срез ~1,6 кГц) подавляет ступеньки обновления и формирует фронт GATE. При включении и без пульта прошивка держит все каналы в нейтрали (0 В).

### A6.4. CV-выходы (X / Y / GATE)

- 3× Thonkiconn TS.
- GATE-out: 0/+5V, фронт от Note On (кнопка Shutter пульта).
- X/Y-out: непрерывное CV из 14-bit MIDI → 16-bit ЦАП → масштабатор. Разрешение с запасом перекрывает 14 бит → нет ступенчатости (§4.3 концепта).
- Выходы с защитой (последовательный резистор 1 кОм + клампы) — стандарт Eurorack.

## A7. Переключение режимов без щелчков (mute/crossfade FSM)

Конечный автомат в MCU при смене MODE:
1. Принят новый MODE (CC#80).
2. **Ramp-down** выходного VCA (или мьют-VCA на выходе ядра) за ~20-40 мс → тишина.
3. Переключение реле и аналоговых ключей топологии в новый режим — в момент тишины, щелчок не слышен.
4. Пауза ~10 мс: контакты реле успокаиваются, узлы нового режима встают (сервы выходят из hold, фаза VCO).
5. **Ramp-up** VCA за ~20-40 мс.

Суммарно ~70 мс (§3.2 концепта: 50–100 мс). Ramp генерится ЦАП (канал F) на ток хвоста второго каскада выходного VCA (A3b, S8). Кривая — S-образная.

Автомат работает от целей: запрос MODE или ROUTE, пришедший посреди цикла, не теряется; из нескольких исполняется последний. Проверено хост-тестами прошивки.

**Тот же FSM обслуживает ROUTE-свитч (pre/post, A3a):** смена порядка core⇄фильтр — тоже под mute, чтобы без щелчка.

ARM (CC#64): второй каскад выходного VCA используется как глобальный gate enable — ARM off → ток управления в ноль (с тем же ramp).

## A8. MIX (clean blend) + двухкаскадный VCA + выход (AUDIO OUT)

- **MIX (dry/wet, clean blend)** — кроссфейд между **clean tap** (A2.5, чистый после входного буфера) и обработанным выходом (сатурация ⇄ фильтр → Tone → Bass). Два OTA/VCA в противофазе от MIX-knob (+ MIX-CV) → сумматор. Сохраняет фундамент/транзиенты. Глобален.
- **Двухкаскадный VCA по схеме «Поливокса»** (A3b) после MIX: первый каскад — LEVEL (ручка + CV), второй — mute: управляется FSM (A7) и ARM (de-click при смене MODE/ROUTE и gate enable).
- Выходной буфер на **TL072 / OPA1642**, низкий выходной импеданс, посл. резистор ~1 кОм (стандарт Eurorack), AC-связь, защита.
- Разъём 3.5mm TS.

## B0. Базовое решение: пульт = донорская дрон-аппаратура

Корпус и органы — **репурпозинг реальной RC/дрон-аппаратуры управления** (прямое семиотическое замыкание §4.1, R3 закрыт). Не проектируем механику с нуля — потрошим донора и ставим свою плату.

- Из донора **родную RF/MCU-плату удаляем**, оставляем: гимбалы, тумблеры/переключатели, потенциометры/триммеры, отсек питания, корпус.
- Ставим **свою плату STM32G431**, которая читает сохранённые органы и отдаёт MIDI (TRS + USB) + опц. CV-out.
- **Джойстик берём с готового гимбала донора** — самоцентрирование решается выбором гимбала, а не доработкой пружин (см. B2).
- Распайка органов донора под наши функции (ARM/MODE/LINK/LEVEL/TONE) — по факту, что есть на конкретном доноре; маппинг гибкий в прошивке.

Следствие: **Range/Offset на пульте НЕ делаем** — пульт отдаёт сырой биполярный жест, а глубину/масштаб/инверсию модуляции крутят **на принимающем модуле** (аттенюверторы CV-ins, §A5). От Befaco-архитектуры берём только биполярную разводку оси (B2).

## B1. Питание и автономность

- **LiPo 1S, 3.7V**, ёмкость под ≥8 ч: оценка потребления (см. §10) → ~**2000-2500 мАч** (1S) с запасом. Финал — после замера прототипа.
- **Зарядка USB-C**: контроллер заряда 1S Li-ion **MCP73831 / TP4056** (с защитой DW01+FS8205 или интегрированный **BQ24075** с power-path, чтобы работать во время зарядки). 5V/up to 2A со стандартного USB-C (без PD; CC-резисторы 5.1 кОм для корректного обнаружения как UFP).
- **Boost до системного rail**: 1S → +5V boost (**TPS61023 / MT3608**) для USB-логики и сенсоров, далее LDO +3.3V (MCU, ЦАП). Для CV-out ±-rail (если CV биполярный) — небольшой **charge-pump/inverter** (TPS60403) или DC-DC до +12/−12 (либо CV-out пульта делаем униполярным 0…+5/+8V — решается единым стандартом линейки, §13-R5).
- **Топливомер**: **MAX17048 / BQ27xxx** (I²C, точный SoC) → индикатор заряда (4 LED или OLED-полоска, §B3).
- **Автоотключение >30 мин простоя**: MCU отслеживает активность (движение джойстика/нажатия), по таймауту — load-switch (**TPS22918** / P-MOSFET) обесточивает rail, MCU уходит в standby/shutdown. Пробуждение — кнопка питания / нажатие джойстика (wake на EXTI).
- Кнопка питания (мягкая, через load-switch).

## B2. MCU, ADC, джойстик

- **MCU: STM32G431** (USB FS, 12-bit ADC × несколько каналов с аппаратным оверсэмплингом).

### B2.1. Джойстик: гимбал донора, Befaco-разводка, гибридное самоцентрирование

- **Источник — родной гимбал донорской аппаратуры** (B0). Сенсор — что стоит у донора: резистивные потенциометры (бюджетные пульты) или Hall (AS5600 / 49E-класс в качественных). Аналоговый фронт-энд адаптируется под факт: pot → делитель/ADC, Hall-pot → ADC, AS5600 → I²C.
- **Самоцентрирование — гибрид дрон-стиля: X(BIAS) центрируется пружиной, Y(DRIVE) свободен (фрикцион/трещотка).** Это **ровно «газовый» гимбал стандартной Mode-2 аппаратуры**: вертикаль = throttle (без пружины, держит позицию) → DRIVE, горизонталь = rudder (пружина в центр) → BIAS. **Механику не дорабатываем** — берём throttle-гимбал донора как есть (Mode-2 → левый стик; Mode-1 → правый).
- **Befaco-разводка биполярной оси**: потенциометр оси запитан между **+Vref и −Vref**, движок даёт биполярное напряжение, **центр = 0 V**. Из этого:
  - **раздвоение сигнала**: буфер (TL072/OPA2188) → (а) level-shift в 0…3.3 V → ADC → 14-bit MIDI; (б) масштабатор → ±5 V CV-out (B5).
  - Один жест → и MIDI на модуль Is My, и аналоговый CV на остальную линейку.
  - **Range/Offset на пульте отсутствуют** (B0): аттенюверсия — на принимающем модуле (§A5). Befaco-аналог Range/Offset переехал на приёмник.
- **14-bit для осей X/Y (обязательно §4.3)**: STM32 ADC 12-bit + **аппаратный оверсэмплинг ×16 → 16 бит** effective → чистые 14 бит после фильтрации. Опрос осей ≥ 1 кГц.
  - Если гимбал на AS5600 (I²C, 12-bit) — оверсэмплинг программный + сглаживание; 12 «железных» бит + усреднение → достаточно для 14-bit без слышимой ступенчатости.
  - Резистивный pot донора: следить за шумом движка → EMA-сглаживание + deadzone, иначе сыпет лишний MIDI.
- **LEVEL / TONE**: потенциометры/триммеры донора → ADC, 7-bit MIDI (оверсэмплинг + антидребезг по гистерезису).
- Калибровка: запись min/max/center каждой оси в flash при сервисном жесте; deadzone вокруг центра (важно для центрирующейся X); опциональная гамма-кривая.
  - Y(DRIVE) свободна → центр не нужен, мапим весь физический ход в 0…14-bit (throttle-логика). X(BIAS) центрируется → центр=mid-scale, ход в обе стороны от центра.

## B3. Органы управления

| Орган | Тип | Подключение | MIDI |
|------|-----|-------------|------|
| ARM | тумблер 2-поз | GPIO + debounce | CC#64 0/127 |
| MODE | тумблер 3-поз (ON-OFF-ON) | 2× GPIO | CC#80 0/64/127 |
| LINK | тумблер 2-поз | GPIO | CC#81 0/127 |
| LEVEL | потенциометр | ADC | CC#7 (7-bit) |
| TONE | потенциометр | ADC | CC#74 (7-bit) |
| Joystick X | Hall/ADC | ADC/I²C | CC#16+48 (14-bit) |
| Joystick Y | Hall/ADC | ADC/I²C | CC#17+49 (14-bit) |
| Joystick press | тактовая кнопка | GPIO + debounce | Note C2 On/Off |
| Foot switch | внешний TS-джек | GPIO + debounce + pull-up | Note C#2 On/Off |
| ARM LED | зелёный | GPIO | зеркалит ARM |
| Activity LED | амбер | GPIO/PWM | моргает по MIDI-трафику/нажатиям |
| Battery ind. | 4 LED или OLED | GPIO / I²C | от MAX17048 |

- **LINK** (связь осей): при LINK on прошивка связывает X и Y (например, синхронное движение — одна ось управляет обеими, или зеркалит) — точная семантика «независимо/синхронно» уточняется (§13-R4).
- Антидребезг тумблеров/кнопок — программный (10-20 мс) или RC + Шмитт.
- Foot-switch джек — TS, нормально-разомкнут/замкнут (поддержать оба типа педалей: автоопределение полярности при включении).

## B4. MIDI out (TRS Type A) + USB-MIDI

- **TRS MIDI OUT**: UART TX (31250 бод) → буфер по стандарту MIDI-TRS Type A: **Tip = signal через 220 Ω, Ring = +3.3V через 220 Ω, Sleeve = GND/shield**. Драйв через буфер (можно с 3.3V rail; ток-петля на приёмнике опто). Защита TVS на джеке.
- **USB-MIDI**: STM32G431 USB FS, класс **USB MIDI 1.0** (или MIDI 2.0/USB-MIDI 2.0, если целимся в будущее — но 1.0 совместим со всем). Тот же поток сообщений идёт и в TRS, и в USB (или выбор по настройке). Пульт виден как class-compliant MIDI-контроллер без драйверов.
- USB-C разъём: D+/D− на USB-PHY MCU, CC-резисторы, VBUS → charger (B1).

## B5. CV out пульта (X / Y / GATE)

Пульт умеет управлять другими модулями линейки напрямую (§3.3, §7 концепта), мимо MIDI:
- Маленький **ЦАП на пульте** (квадро 12-16 bit, напр. **MCP4728** I²C 12-bit или **DAC8554** SPI) → 3 канала: X, Y, GATE.
- Масштабатор под системный CV-стандарт линейки: **X/Y → ±5 V биполяр (центр джойстика = 0 V), GATE → 0…+5 V** (R5).
- Для биполярного rail от 1S LiPo нужен отрицательный источник: **charge-pump инвертор** (TPS60403/ICL7660) или малый DC-DC. (R10.)
- 3× джек 3.5mm TS — **добавляются в корпус донора** (сверловка), на доступной кромке.
- CV генерятся **параллельно MIDI** из тех же сырых данных джойстика/ножника, локально на пульте — независимо от того, подключён ли модуль Is My. **Без Range/Offset** (B0): сырой биполярный жест; подстройка глубины — на приёмном модуле.

## B6. Механика пульта

**Решение: донор** (R3 закрыт). Корпус, гимбалы, органы — от реальной RC/дрон-аппаратуры (B0).
- Габарит/эргономика определяются донором; ориентир ~180×100×40 мм.
- Throttle-гимбал (Mode-2 левый / Mode-1 правый) → джойстик DRIVE/BIAS с нужным самоцентрированием (B2.1), без доработки.
- Родные органы донора мапятся под ARM/MODE/LINK/LEVEL/TONE (что доступно физически); недостающее добавляется минимально.
- В корпус добавляются: **USB-C** (заряд + USB-MIDI), **TRS MIDI OUT**, **foot-switch jack**, **3× CV-out** — сверловкой по доступным кромкам.
- Наша плата STM32G431 крепится на место удалённой RF-платы донора.
- Сохранить родные индикаторы донора, если есть, под ARM/activity/battery (иначе добавить LED/OLED).

# ЧАСТЬ C. ПРОШИВКА

Общий стек: **STM32 HAL/LL + бэр-метал C** (или Zephyr, если хотим переносимость; для простоты — bare-metal/HAL). Один репозиторий, две прошивки (`pult/`, `module/`), общий заголовок с MIDI-маппингом (`midi_map.h`) — единственный источник истины по CC/нотам.

## C1. MIDI mapping (канонический — `firmware/common/midi_map.h`)

Канал по умолчанию 1 (переключаемый, хранить в flash).

| Источник | MIDI | Разрешение | Примечание |
|---------|------|-----------|-----------|
| Левый стик X — BIAS | CC#16 (MSB) + CC#48 (LSB) | 14-bit | momentary: 8192 = центр |
| Левый стик Y — DRIVE | CC#17 + CC#49 | 14-bit | rate: накопленное значение 0…16383 |
| Правый стик Y — CUTOFF | CC#18 + CC#50 | 14-bit | rate |
| Правый стик X — RESO | CC#19 + CC#51 | 14-bit | momentary |
| Колёсико (dial) | CC#20 | 7-bit | → нормаль MIX-in; 64 = без сдвига |
| ARM (кнопка RTH) | CC#64 | 0/127 | toggle в прошивке пульта |
| MODE (слайдер) | CC#80 | 0/64/127 | SHAPER/RING/GATE |
| LINK (кнопка Fn) | CC#81 | 0/127 | toggle |
| GATE (кнопка Shutter) | Note On/Off | нота C2 (36) | |
| Heartbeat | Active Sensing 0xFE | — | каждые 250 мс; тишина дольше 500 мс = обрыв линка |
| ~~LEVEL, TONE~~ | CC#7, CC#74 | — | пульт не шлёт: это ручки модуля. Номера зарезервированы |
| ~~Foot switch~~ | нота C#2 (37) | — | педали нет; модуль принимает ноту как второй источник GATE |

14-bit паттерн: всегда слать MSB (CC#16…19) **перед** LSB (CC#48…51); приёмник применяет значение по приходу LSB (или по таймауту 20 мс, если LSB не пришёл — fallback на MSB·128).

## C2. Прошивка пульта

Скелет — `firmware/pult/main.c`, покрыт хост-тестом `smoke_pult`.

```
init: clocks, USB-MIDI device, ADC (oversample ×16), калибровка из flash,
      стартовый снапшот состояния (ARM, LINK, MODE, dial, четыре оси).

каждую 1 мс — оси:
  читать 4 оси (16-bit после оверсэмплинга), EMA, калибровка min/max/center
  горизонтали (BIAS, RESO): momentary — позиция, deadzone у центра
  вертикали (DRIVE, CUTOFF): rate — отклонение × прошедшее время → накопленное значение
  если изменилось больше порога и не чаще 200 Гц на ось:
     слать 14-bit пару CC (MSB, затем LSB)

каждые 10 мс — органы:
  кнопки RTH / Fn → toggle ARM / LINK → CC#64 / CC#81
  кнопка Shutter → Note On/Off C2
  слайдер → CC#80; колёсико → CC#20 (гистерезис)

каждые 250 мс: Active Sensing (0xFE)

LED: USB-ok, activity, ARM, сервис (калибровка / долгий простой)
```

Особенности:
- **Anti-jitter** на осях: порог изменения + сглаживание (EMA), иначе шум ADC сыплет лишний трафик.
- **Rate-оси считают время, а не вызовы**: задержка главного цикла не меняет скорость оси, провал дольше 50 мс не даёт скачка.
- Калибровка: удержание Power при подключении кабеля → прогнать оси по краям → Power. Центр усредняется; негодный результат не записывается.
- Питание только от VBUS: батареи, зарядки и автоотключения нет. В комп пульт втыкается как обычный USB-MIDI контроллер.

## C3. Прошивка модуля

Скелет — `firmware/module/main.c`, покрыт хост-тестом `smoke_module`.

```
init: clocks, USB-host, SPI DAC8568, GPIO (реле, ключи, свитч ROUTE, LED),
      калибровочные таблицы, safe state: mute, оси в нейтрали, VBUS выключен.

USB / MIDI:
  устройство на линиях CC → включить VBUS → энумерация пульта
  USB-MIDI пакеты → MIDI-байты → парсер (running status; realtime его не сбивает)
  CC#16/48 … CC#19/51 → 14-bit оси (MSB → LSB, таймаут 20 мс)
  CC#20 → dial; CC#64 → ARM; CC#80 → MODE (цель для FSM); CC#81 → LINK
  Note C2 On/Off → GATE (сразу, одной записью в ЦАП)

control loop (1 кГц):
  оси → коды ЦАП через калибровку: A=DRIVE, B=BIAS, C=CUTOFF, D=RESO, E=GATE, H=dial
  панельный свитч ROUTE → цель для FSM
  FSM mute (MODE и ROUTE): рампа вниз 30 мс → переключение → пауза 10 мс → рампа вверх 30 мс
  ARM: off → mute-каскад плавно в ноль; on → плавно вверх

линк:
  жив = USB-стек видит пульт и байты (хотя бы Active Sensing) идут чаще 500 мс
  потерян → значения осей держим, GATE отпускаем, индикация
```

Особенности:
- **Калибровочные LUT** на каждый параметр: компенсируют нелинейность тракта и подгоняют диапазон ЦАП под рабочую область конкретного донорского MOSFET (заполняются при сборке экземпляра — связь с уникальностью edition §6.3).
- Сервопетля SHAPER (§A3.4) — **аналоговая** (не в прошивке), MCU только выставляет опору тока покоя через ЦАП-канал G.
- Фронт GATE формирует RC на выходе канала ЦАП (≈ 0,2 мс), программного «доползания» нет.
- Безопасное состояние при старте: mute и нейтраль осей, пока пульт не прислал своё состояние.

## C4. Общий заголовок `midi_map.h`

## Модуль
- MCU — по итогам It-2 (D6): STM32G431 + **MAX3421E** с кварцем 12 МГц либо RP2040 с QSPI-flash и кварцем
- USB-порт пульта: гнездо USB-C, ESD **USBLC6-2SC6**, ключ VBUS **TPS2553**, резисторы Rp 36k ×2 на линиях CC
- Питание: buck 12→5 (**TPS54202 / LMR51420**), **MCP1700-3.3**, стабилизатор ядра +9V (**78L09 / LM317L**)
- ЦАП: DAC8568 / AD5668 (16-bit octal) ×1; Vref: REF3040 (+4.096V) ×1 с буфером OPA192
- ОУ тракта и управления: OPA1642 / TL072 — порядка 45 секций (≈ 23 сдвоенных корпуса), точный счёт при разводке; вычитатели VCA — отдельно, только TL072 ×1 (сдвоенный, S8)
- Прецизионный ОУ серва: OPA2188 (дуальный, 2 сервы на 2 каскада) ×1
- OTA: LM13700 ×4 — pre-HPF и INPUT DRIVE (один корпус), MIX dry/wet, Tone, демпфер резонанса VCF, VCO режима RING
- **Программируемые ОУ К140УД12 / КР140УД1208 ×2** — ядро VCF по схеме «Поливокса» (S5); замены: µA776, MC1776, NTE888M, LM4250 (R24)
- **Дифференциальные усилители К118УД1Б ×2** — выходной VCA по схеме «Поливокса» (S8); замена: дискретно на CA3046 (R24)
- Обвязка VCF и VCA: TL071 ×1, 2N3904 ×1, BC547 ×1
- Компараторы: LM311 ×3 (Шмитт VCO, ШИМ, гейт)
- Драйвер затворов: **TC4428** ×1 (два комплементарных выхода, 0/+9 В)
- Реле сигнальные DPDT (TQ2-12V / G6K-2) ×2 — перекоммутация стока и истока по режимам (S4.4)
- Аналоговые ключи: **DG333A** ×3 (режимы ядра ×2, ROUTE ×1)
- Свитчи на панели: MODE-F (LP/BP), ROUTE (pre/post) ×2
- **Донорский ESC N-MOSFET ×2** (на сокетах) — два каскада SHAPER, они же ключи RING/GATE; *provenance items*
- Разъёмы: Thonkiconn ×13 (8 CV-in, 3 CV-out, audio in/out), USB-C, питание Eurorack 16-pin
- Потенциометры ×9: DRIVE и BIAS (аттенюверторы), LEVEL, TONE, HPF (логарифмический), MIX, BASS, CUTOFF, RESONANCE
- Многооборотные подстроечники ×7: смещение и масштаб среза VCF, баланс двух каскадов VCA, нуль INPUT DRIVE, баланс ячеек RING, глубина ШИМ
- LED ×2, ферриты, TVS, пассив
- Панель + PCB (20 HP, R15)

## Пульт
- **DJI C5 (RC-N1 / RC231)** ×1 — корпус, гимбалы, кнопки, слайдер, колёсико, LED, окно USB-C; *provenance/семиотика*
- Наша плата вместо родной: STM32G431 (USB FS device) ×1, MCP1700-3.3, резисторы Rd 5.1k ×2 на линиях CC, разъёмы под родные шлейфы
- USB-C: родной порт донора или мини-плата с гнездом в родное окно
- Батареи, зарядки, CV-выходов и дополнительных отверстий нет (`05_pult_dji_c5.md`)
