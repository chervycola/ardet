# Перенос бота: удаление старого и запуск нового

Проверенный порядок (мы так уже переезжали с @zel_discret_bot).
Главное правило: **сначала поднимаем нового, потом гасим старого** —
ни минуты без работающего бота.

Целевое имя: **@dskrt_bot** (если занято — @dskrt_forum_bot, @dskrtspacebot;
юзернейм бота обязан кончаться на `bot` и быть не короче 5 символов).

## Шаг 1 · Создать нового бота

1. Открыть **@BotFather** → `/newbot`.
2. Имя (отображаемое): `ДИСКРЕТ`.
3. Юзернейм: `dskrt_bot`.
4. BotFather пришлёт **токен** — скопировать целиком, никому не пересылать
   (ни в чат, ни в репозиторий; токен живёт только в `config.php` на хостинге).

Косметика там же в BotFather (по желанию, но лучше сразу):
- `/setuserpic` → аватар (пиксельный Д, `branding/photos/лого.png`);
- `/setdescription` → «Научно-технический форум творческого приборостроения.
  19.09.2026 · Зеленоград · МИЭТ. Девайсы, программа, билеты.»;
- `/setabouttext` → короткая строка для профиля: «ДИСКРЕТ · 19.09.2026 ·
  Зеленоград · дискрет.рф».

## Шаг 2 · Переключить вебхук на нового

1. На хостинге рег.ру открыть `config.php` и заменить **только** строку
   `BOT_TOKEN` на новый токен. `APP_URL`, `SETUP_SECRET` и остальное не трогать.
2. Открыть в браузере:
   `https://дискрет.рф/bot.php?setup=ВАШ_СЕКРЕТ`
3. Убедиться, что в ответе **три `"ok": true`**: setWebhook, setMyCommands,
   setChatMenuButton. Если `error_code 404 / Not Found` — токен вставлен
   с ошибкой, перекопировать из BotFather (`/mybots` → бот → API Token).

## Шаг 3 · Проверить

1. Написать новому боту `/start` — должно прийти меню с кнопками,
   включая «🟥 Открыть ДИСКРЕТ» и «🎟 Билеты».
2. Кнопка-меню слева от поля ввода должна открывать приложение.
3. Если бот молчит — диагностика:
   `https://дискрет.рф/bot.php?ping=ВАШ_СЕКРЕТ&chat=ВАШ_CHAT_ID`
   (покажет ответ Telegram и текущий APP_URL).
4. Проверить приём формы обратной связи из приложения (сообщение должно
   упасть админу).

## Шаг 4 · Погасить старого (@discret_space_bot)

Не удаляйте сразу — на него ещё ведут старые посты. Правильно так:

1. В BotFather: `/mybots` → @discret_space_bot → **API Token → Revoke** —
   старый вебхук умирает, бот перестаёт отвечать.
2. Там же `/setdescription` для старого: «Мы переехали → @dskrt_bot».
   Кто зайдёт по старой ссылке — увидит, куда идти.
3. Обновить ссылку на бота в шапке/закрепе канала и в будущих постах
   (в текстах `branding/press/` уже заменено).
4. Через 2–3 недели, когда трафик на старого иссякнет:
   `/mybots` → @discret_space_bot → **Delete Bot** → подтвердить фразой.
   Удаление безвозвратно; юзернейм освобождается не сразу и не всегда —
   поэтому и нужен пункт 2, а не расчёт на редирект.

## Что где обновляется при переезде (чек-лист)

- [ ] `config.php` на хостинге — новый BOT_TOKEN (единственная правка);
- [ ] `?setup=СЕКРЕТ` — прогнать один раз;
- [ ] шапка и закреп Telegram-канала;
- [ ] будущие посты — тексты в `branding/press/channel-posts.md` уже
      указывают @dskrt_bot;
- [ ] карточка renders/tickets/tickets-01 — уже перегенерирована;
- [ ] QR-коды на печатных материалах, если успели напечатать со старым
      адресом — перепечатать (ведут на t.me/discret_space_bot).

Файлы `bot.php` / `.htaccess` / `index.html` при смене бота **не меняются** —
вся привязка живёт в токене внутри `config.php`.
