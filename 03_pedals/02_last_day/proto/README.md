# proto/ — bench-план прототипирования Last Day

Методики настольных стендов («ригов») для проверки физики Last Day до любой разводки платы. Главный принцип плана: **сначала прототипируем то, что может убить концепт, а не то, что приятно паять**. Узлы ранжированы по «неизвестность × последствия»:

- **A — экзистенциальные риски:** емкостный масляный пикап и язычок-резонатор.
- **B — рабочие риски:** мотор с PLL и солнечный каскад.
- **C — известная схемотехника:** EQ, FX, перформ. Её не паяют, пока категория A не дала «go».

## Статус

- План активен с 2026-07, но **ни один риг пока не собран.** Таблицы «Журнал» во всех четырёх методиках пустые.
- Аудиозаписи по плану складываются в `proto/audio/` с именами `rigN_YYYY-MM-DD_описание.wav`. Этой папки пока нет ни в одной ветке.
- Первая волна — Rig #1 и Rig #2 параллельно, бюджет ~$65, одни выходные.

## Порядок и вехи

```
Rig #1 (oil pickup) ──┬─→ Rig #3 (motor+PLL) ──→ M1: делэй звучит
Rig #2 (tongue) ──────┤   (параллельно с #1)
Rig #4 (solar) ───────┴─→ категория C → M2: полный breadboard → M3: KiCad rev A
```

- **M0** — Rig #1 и Rig #2 дали go / no-go. Продолжаем как задумано или включаем зафиксированный fallback.
- **M1** — Rig #1 и Rig #3 вместе: гитара → диск → эхо. Записать аудио и датировать.
- **M2** — полный breadboard-«франкенштейн»: пикап, мотор, язычок-EQ, солнечный каскад и 1–2 character FX.
- **M3** — схема в KiCad rev A на измеренных, а не расчётных номиналах.

## Как пользоваться

Каждая методика устроена одинаково: BOM, сборка, процедура, критерии go / борьба / no-go, журнал. Результаты измерений записывайте прямо в таблицу «Журнал» в файле рига. Наглядная версия плана с иллюстрациями — листы 03–05 и 11 туториала [../tutorial/last_day_tutorial.html](../tutorial/last_day_tutorial.html).
