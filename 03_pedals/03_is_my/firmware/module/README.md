# firmware/module — прошивка модуля

Скелет прошивки модуля Is My (STM32G431): MIDI с пульта переводится в управляющие напряжения. Архитектура описана в `02_technical.md` §C3 и `05_pult_dji_c5.md` §4.

| Файл | Что |
|---|---|
| [`main.c`](main.c) | MIDI-парсер: running status, 14-битные пары MSB→LSB с таймаутом, фильтр канала. Калибровка scale/offset перед ЦАП. FSM mute и crossfade для MODE и ROUTE с рампой 30 мс. ARM работает как глобальный gate. При потере линка держатся последние значения, при старте модуль в безопасном состоянии (mute) |
| [`bsp.h`](bsp.h) | Интерфейс слоя железа: время, приём MIDI через USB-host (MAX3421E по SPI) и состояние линка, кадр в ЦАП по SPI, мультиплексоры MODE/ROUTE (DG419), панельный свитч ROUTE, светодиоды, flash для калибровки |
| [`dac8568.h`](dac8568.h) | Минимальный драйвер DAC8568 (16 бит, 8 каналов, SPI): формат 32-битного кадра, раскладка каналов A–H по `05` §4.2, работа от внешней опоры REF3040 |

Статус: скелет. Логика покрыта smoke-тестом в [`../host_test/`](../host_test/). В вычитке [`../../07_review_and_plan.md`](../../07_review_and_plan.md) найдены ошибки, которые smoke не ловит. E1: в `ramp_shape()` сдвиг `>>45`, нужен `>>30`, поэтому рампа превращается в ступеньку. E2: де-клик GATE слишком медленный. E3: запрос MODE/ROUTE теряется, если приходит во время рампы. E4: потеря линка определяется ложно. Пока не принято D1–D7, всё это не исправлено. Комментарий `bsp_init()` в `main.c` (UART RX 31250) остался от TRS-линка: по `bsp.h` MIDI приходит через USB-host. В `07` это не отмечено.
