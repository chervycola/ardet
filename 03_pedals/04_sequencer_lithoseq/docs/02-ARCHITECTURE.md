# 02 — Системная архитектура стенда v1

## Блок-схема

```
                 ┌─────────────────────────────────────────────┐
  подсветка      │                  STM32H7/F4                 │
 ┌─────────┐     │  ┌────────┐  ┌──────────┐  ┌─────────────┐  │
 │ LED-панель│   │  │ DCMI+DMA│→│ Пайплайн │→│  Метрики    │  │
 │ + диффузор│   │  │ (кадр)  │  │ crop/gray│  │ D,S,R (+G) │  │
 └────┬────┘     │  └────────┘  │ downsample│ └──────┬──────┘  │
      ↓ просвет  │       ↑      │ flat-field│        ↓         │
 ┌─────────┐     │   OV7670/    └──────────┘  ┌─────────────┐  │
 │ ПЛАСТИНА │    │   OV2640                   │  Плейхед    │←── clock
 │ (образец) │   │                            │ (траектории)│  │  (USB/джек)
 └────┬────┘     │                            └──────┬──────┘  │
      ↓          │                                   ↓         │
 ┌─────────┐     │                            ┌─────────────┐  │
 │  КАМЕРА  │───→│                            │   Маппинг   │  │
 └─────────┘     │                            │ квантайзер, │  │
                 │                            │ Reveal/Comp.│  │
                 │                            └──┬───┬───┬──┘  │
                 │       USB CDC (карта+метрики) │   │   │     │
                 │       USB MIDI (фаза 2) ←─────┘   │   │     │
                 └───────────────────────────────────┼───┼─────┘
                                                     ↓   ↓
                                          I2C DAC MCP4728 → op-amp → CV/gate
                                                     (фаза 3)
```

## Тракт данных

1. **Захват.** DCMI + DMA, двойная буферизация, QVGA (320×240) grayscale
   (Y-канал YUV). Кадр приходит целиком в RAM (H7: AXI SRAM; F407: 76 КБ на
   кадр Y — помещается). Контроллер освещения (GPIO: просветная панель,
   диффузное кольцо, 4 группы косых LED) синхронизирован с захватом; в
   режиме REFLECT-4 карта собирается из 4 кадров (03 §3а), для остальных
   ступеней конвейера это прозрачно — дальше идёт готовый «сырой» кадр.
2. **Кадрирование.** Из кадра берётся квадратная ROI, соответствующая окну
   25×25 мм (границы ROI определяются один раз при юстировке, храним во
   flash/EEPROM-эмуляции).
3. **Даунсемплинг.** ROI → 32×32 усреднением по блокам (box filter). Заодно
   считаются 16×16 и 8×8 (пирамида усреднением 2×2).
4. **Калибровка.** map[i] = clamp((raw[i] − dark[i]) * gain[i]), где dark/gain
   из flat-field процедуры (пустая пластина + тёмный кадр). Автоусиления по
   кадру НЕТ (D6). Экспозиция камеры фиксируется вручную при юстировке.
5. **Метрики.** На каждом кадре: D-карта (сглаженная), S-карта, скаляр R.
   Определения и формулы — 05 §3.
6. **Плейхед.** Генератор траекторий выдаёт последовательность индексов
   (x,y) по тикам клока. Читает значения из карт в текущей позиции.
7. **Маппинг.** Значения → нота (квантайзер с маской шкалы от R), gate,
   2 aux CV. Пресеты Reveal/Compose — два набора коэффициентов маппинга,
   не две ветки кода (05 §5).
8. **Выходы.** Фаза 2: USB-MIDI. Фаза 3: MCP4728 по I2C → op-amp каскад.

## Разделение частот обновления

- Кадр/метрики: 5–15 Гц (асинхронно, по готовности DMA).
- Плейхед/ноты: по клоку, 0.5–50 Гц (музыкальный темп).
- Карта для плейхеда подменяется атомарно между тиками (double buffer
  указателем) — паттерн не «рвётся» посреди шага.

## Выбор MCU-платы

Основной: **Nucleo-H743ZI2** (DCMI разведён на морфо-штырях, 1 МБ RAM,
USB FS, запас по всему). Бюджетная альтернатива: DevEBox STM32H743 /
STM32F407VET6 + OV7670 без FIFO (DCMI). Прошивка пишется против HAL с
тонкой прослойкой (05 §1), чтобы смена платы не трогала логику.

## Что переезжает в модуль без изменений (фаза 4)

Пайплайн, метрики, плейхед, маппинг, протокол отладки. Меняются: источник
клока (джек), UI (энкодер/кнопки/CV-входы), выходной каскад, питание.
Граница переносимости зафиксирована в 05 §1 — «ядро не знает про железо».
